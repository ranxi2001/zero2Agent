4. 高准确性场景怎么控制幻觉？

这个问题问的是Agent在需要精确输出的场景下如何保证可靠性。

我的回答：

控制幻觉有几种手段：

约束解码：对于特定输出格式，用JSON Schema约束LLM的输出结构
检索增强：所有事实性内容必须来自检索结果，而不是依赖模型参数记忆
引用溯源：每个事实点都带上来源引用
自我反思：生成后让模型自检一遍，或者用另一个模型做验证

最核心的一点：凡是涉及具体数据（时间、地点、数字）的，必须从工具返回结果中提取，不允许模型自己编。

5. 幻觉率和引用错误率多少？业务上能否接受？

这道题问的是实际指标。

我的回答：

在我们的评测集上，幻觉率大概在3%-5%，引用错误率在2%左右。

业务上能不能接受取决于场景：

日程提醒类：不能接受，错了就是事故
信息汇总类：可以接受一定容错，但要有人工确认环节

面试官追问：怎么定义幻觉和引用错误？

我说：幻觉是"模型说了检索结果中没有的内容"，引用错误是"引用了文档但内容对不上"。前者更严重。

6. AI生成代码安全性问题如何解决？

这道题问的是代码执行的安全边界。

我的回答（跟面试官确认了一下理解）：

AI生成的代码不能直接在宿主环境里跑，必须用沙箱隔离。具体来说：

用Docker容器限制资源（CPU、内存、磁盘）
设置网络隔离，禁止访问内网
限制系统调用，不允许文件写入和进程创建
设置超时和内存上限，防止死循环和OOM

面试官追问：Python的exec和eval能直接用吗？

我说：不能。exec在Python里是不安全的，可以执行任意代码。即使限制了globals，仍然有办法绕过。必须用沙箱，比如pypy在受限环境中运行，或者用nsjail这种系统级隔离。

8. 长期/中期/短期记忆分别怎么设计？

这道题考的是记忆分层。

我的回答：

短期记忆：当前会话的消息列表 + 工具调用结果，存在内存里
中期记忆：跨会话但近期（比如过去7天）的对话摘要，存在Redis里
长期记忆：用户偏好、历史事实、周期性任务等，存在向量数据库里

每次新请求来了之后：

面试官追问：三个记忆怎么分层存储？

我说：短期用内存（快），中期用Redis（持久化+快），长期用向量库+MySQL（持久化+检索）。

9. 记忆滚动更新、摘要压缩、结构化压缩怎么做的？

这道题问的是记忆维护的具体机制。

我的回答：

滚动更新：当对话轮次超过阈值（比如20轮），用滑动窗口丢掉最早的消息，但保留系统指令和关键事实。

摘要压缩：每N轮对话触发一次摘要：

1
	
旧摘要 + 最近N轮对话 → LLM → 新摘要

结构化压缩：把对话中的事实抽取成结构化三元组：

1
	
"明天下午三点有会" → {type: "schedule", time: "2026-07-30T15:00", event: "会议"}

三种方式配合使用：滚动更新保证不超窗口，摘要压缩保留语义，结构化压缩便于检索。

10. Multi-Agent如何协作？ReAct、Path-Act

这道题问的是多Agent协同模式。

我的回答：

我们主要用了两种协作模式：

ReAct模式：单个Agent内部循环执行"推理→行动→观察"。适用于一个Agent独立完成任务的场景。

Path-Act模式：多个Agent按路径串行或并行执行。主Agent负责任务分解和路由，子Agent分别处理子任务，最后汇总结果。

协作流程：

不同点是：

ReAct：单Agent，循环迭代
Path-Act：多Agent，路径编排

12. Badcase回流到SFT的完整链路？

这道题问的是数据闭环。

我的回答：

完整链路是这样的：

1
	
线上Badcase → 人工标注修正 → 构造训练样本 → SFT微调 → 离线评测 → 灰度上线 → 线上验证

每一步：

评测：在Badcase集合上验证修复效果，同时做回归测试确保不引入新问题
灰度上线：小流量验证，观察Badcase率变化

16. Loop Engineering是什么？

这道题问的是Agent循环控制。

我的回答：

Loop Engineering指的是对Agent循环执行过程的精细化控制工程。

核心要素：

循环条件：什么时候继续、什么时候终止
步数限制：最大迭代次数
状态管理：每次迭代更新上下文
异常处理：工具超时、返回错误时的策略
观察裁剪：工具返回内容太长时如何截断

其实就是把Agent的循环从"while true"变成一个可控、可观测、可终止的工程系统。

17. Graph Engineering是什么？和Loop Engineering有什么区别？

这道题问的是两个工程概念的对比。

我的回答：

Graph Engineering：把Agent任务流程组织成有向图，节点是步骤（推理、工具调用、条件判断），边是流转路径。支持分支、并行、循环、合并。

Loop Engineering：关注的是单个Agent的循环迭代控制，强调的是"步数管理"和"状态维护"。

区别：

关注层级

	

任务流程编排

	

单次循环控制




结构

	

图（节点+边）

	

循环（推理→行动→观察）




适用

	

复杂多步骤任务

	

ReAct类Agent




粒度

	

粗（步骤级）

	

细（单次迭代级）

两者可以结合：Graph里每个节点可能内部就是一个Loop。

def longest_common_substring(s1: str, s2: str) -> str:
    m, n = len(s1), len(s2)
    # dp[i][j] 表示 s1[:i] 和 s2[:j] 的最长公共子串长度
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    max_len = 0
    end_pos = 0
     
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
                if dp[i][j] > max_len:
                    max_len = dp[i][j]
                    end_pos = i
     
    return s1[end_pos - max_len: end_pos]

DeepSeek的面试官有个特点：追问特别多。每个问题答完之后，他会根据你的回答继续往下挖，挖到你答不上来为止。这其实是在找你的能力边界。
