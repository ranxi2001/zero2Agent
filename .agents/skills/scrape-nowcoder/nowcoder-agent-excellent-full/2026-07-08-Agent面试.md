Agent面试
牛客上能看到不少关于 Agent 应用开发岗位的面试经验。我花了一晚上的时间，把相关面经做了梳理，又结合自己最近真实参与面试的感受，有一些感受
整体来看，主要有这几点：
第一，Agent 应用开发表面上看是 AI 方向，但岗位底层仍然偏后端开发。不同的是，它不只考察后端工程能力，还要求你理解 Agent 这个细分方向的核心知识，尤其是对评测体系要有基本认知。传统后端岗位通常不会重点关注测试集构建、效果评估、评分标准设计这些内容，但在 Agent 系统里，这些恰恰非常关键。因为 Agent 不是一次性写完就结束的功能，而是一个需要持续优化、反复迭代的系统。怎么判断它变好了？怎么知道改动有没有带来负面影响？这就离不开测试集和评测标准。所以没有 AI 项目经验的同学，尤其要补上这一块。
 第二，项目质量非常重要。简历里的项目不能让面试官一看就觉得只是 Demo 或玩具项目。做 Agent 项目的时候，一开始就要围绕真实落地场景去设计，而不是为了堆技术名词。现在比较常见、也比较容易讲清楚价值的方向，是帮助企业内部提升效率。易让面试官相信它具备业务价值。这也是我自己这段时间做 Agent 项目后的一个体会。
第三，要真正理解并熟悉 agentic coding。也就是说，你不能只是听说过 ClaudeCode、Codex 这类 coding agent，而是要实际用它们完成过较完整的项目开发，并且沉淀出自己的使用方法。比如如何拆需求、如何控制 Agent 执行过程中不跑偏、如何做代码审查、如何保证最终交付质量。这部分现在已经越来越容易被问到，所以也需要提前做针对性准备。 #发面经攒人品#
