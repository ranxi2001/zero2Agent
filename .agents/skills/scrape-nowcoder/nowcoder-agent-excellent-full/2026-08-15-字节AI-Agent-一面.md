前半段主要聊我做的 AI Agent 媒体生成系统。原来任务串行执行比较慢，我后来做成 Orchestrator + Worker 的并发架构，把任务拆开后用容器并行跑，再用 LLM Judge 做质量检查和失败重试。

性能优化

又追问了一个延迟优化项目。我通过 trace 定位到工具调用链路开销比较大，后面调整调用方式和调度流程，把一次完整生成的延迟从二十多秒压到了几秒。面试官比较关注我是怎么定位瓶颈、怎么验证优化有效的。

Coding 1：找静默区间给一组会议里的说话时间段，找出没人说话的区间。我先按 start 排序，一边合并区间，一边比较下一个 start 和当前最大 end，中间有空档就是 silence

Coding 2：找多人同时说话Follow-up 是找至少两个人同时讲话的时间段。我用扫描线，把开始和结束拆成 event，维护当前活跃人数，人数从 1 变 2 时记录开始，从 2 降到 1 时结束。

反问最后聊了岗位更偏后端还是 Agent，以及 Team Match。面试官说团队比较强调 High Agency，工程师会从想法、实现一直做到上线
